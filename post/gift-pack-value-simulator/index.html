礼包数值，跑出来

2026-11-20 • 3 分钟阅读 • 游戏设计 · 数值 · 概率

集卡礼包改一个保底参数，单包期望会动多少？这个问题靠感觉答不了，但几百行的模拟器可以。我把整套机制参数化成一个单文件模拟器：蒙特卡洛和解析近似互相校验，一条命令扫完整个参数档位。这篇文章记录它的做法，以及扫出来的几个反直觉结果。

机制

一套典型的集卡礼包，五层结构：

  • 每包开 N 张卡，N 可以是小数期望（4.2 = 20% 开 5 张，80% 开 4 张）
  • 每张卡按等级权重 roll 星级，各星级有对应价值；有概率转化为黄金卡，价值乘一个大倍率
  • 每张普通卡有 dup 概率是重复卡
  • 软保底：连续开出重复卡 n 张，下一张以 n×M 的概率触发保护（封顶 100%）。触发后给黄金 Lucky 卡或一张缺失卡，计数器清零；开出普通新卡也清零
  • 硬保底：连续 K 包没出黄金 Lucky，下一包必出一张——照常开满，其中一张替换成黄金 Lucky，其余卡照常走保底判定

两把尺子

只跑蒙特卡洛是危险的：写错一行逻辑，模拟照样出数，你分不清是真规律还是 bug。所以模拟器里同时跑两把尺子，蒙特卡洛和解析近似。

解析链四步：连续重复次数的平稳分布 → 单张触发率 λ → 单包至少触发一次的概率 g → 硬保底服从几何分布。最后期望就是一个三项式：

const ev =
  cfg.base +
  (cfg.count - pHard) * perCardEV +
  cfg.lucky * (pHard + (1 - pHard) * cfg.count * lambda * cfg.pGolden);

推导忽略「硬保底清零截断计数器」这一个二阶效应，代价是解析值系统性偏高：触发率高约 12%，期望端偏差在 1% 量级。实测对照：默认参数百万次模拟，两者偏差 0.014%；扫到最极端档（重复率 1.0）偏差约 1.3%。

两把尺子对不上，要么模拟有 bug，要么近似假设被打破——无论哪种，你都想知道。这就是交叉验证的价值：它不是让数字更准，是让错误现形。

扫档

一条命令按重复率 0 到 1.0 扫七档，复现整张结果表（以下为 10 万次实测，金额单位：金币）：

0.2 6,614,902 6,635,959 0.0715 0.0623 0.0465
0.4 6,849,297 6,863,223 0.0792 0.0561 0.1164
0.5 7,027,528 7,028,511 0.0849 0.0512 0.1672

三行结果值得停一下。

重复率 0 时，黄金 Lucky 产出 = 硬保底占比 = 1/15。 没有软保底可触发，全部产出来自硬保底的几何分布，模拟值精确踩在理论值上。这是模拟器正确性的免费自检。

重复率越高，软保底触发越频繁，硬保底反而越少出现。 重复率 1.0 时，62.6% 的包靠软保底出卡，硬保底占比被压到 2.2%——软保底总是抢在硬保底前面触发，把硬保底架空了。

在这套参数下，重复不是损失，是保底的燃料。 单包期望从 651 万（重复率 0）涨到 882 万（重复率 1.0）：重复卡喂大了触发频率，触发喂大了黄金 Lucky 产出。直觉说重复让玩家难受，数字说重复在推高期望——两条都对，怎么权衡是设计判断，不是模拟器的事。

最大的杠杆

硬保底的 K 是整套机制里最大的一个旋钮。默认 K=14 时单包期望约 703 万；把它收到 4，期望涨到 1090 万，+55%，黄金 Lucky 产出从 8.5% 涨到 21.6%。

一个整数参数，半个期望。调参时先动它，再看别的。

工程上

一个文件，约 280 行 TypeScript，bun 直接跑，零依赖：

  • 参数全走命令行（--dup 0.5 --hard-n 4），默认值是一套演示口径，不对应任何线上配置
  • mulberry32 种子随机，同一个 seed 出同一个结果，数字可以复现
  • 输入校验挡住概率越界、权重和为零这类配置错误
  • --sweep 一键扫档，--times 1000000 把波动收紧到 ±0.1%

商业化上

礼包期望是调参的锚。每次动保底步长、硬保底 K、黄金概率，先跑模拟看期望曲线，确认方向再进测试。同品类产品的集卡系统结构大同小异，这套模拟器参数化到可以直接换算别家机制——竞品的礼包设计，也能用同一把尺子量一遍。

最后

数值必须跑模拟，体验必须真实感知——两者缺一不可。模拟器的价值不是给出答案，是把讨论从「我觉得」拉到「数字说」：期望、触发率、保底占比摆上桌面之后，剩下的部分——这个数字给玩家的感受对不对——才轮到设计判断。

参数往哪个方向调，是设计意图；模拟器只负责告诉你，这一步走了多远。
